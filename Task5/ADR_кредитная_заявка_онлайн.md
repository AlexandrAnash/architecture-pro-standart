### **Решение**

Диаграммы:

- [Диаграмма контекста](./C4_context_кредит_онлайн.png)
- [Диаграмма компонентов](./C4_component_кредит_онлайн.png)

Расширяется платформа из MVP депозитов: добавляются два сервиса и два адаптера, каналы получают кредитные разделы. Кредитный конвейер и скоринг дорабатываются минимально, АБС — только в части поиска заявки и зачисления средств.

Состав новых компонентов:

| Компонент | Технологии | Назначение |
|---|---|---|
| Сервис кредитных заявок | Java 17, Spring Boot, PostgreSQL | Единый реестр заявок из всех каналов, контроль дублей, маршрутизация, статусы |
| Сервис предодобренных предложений | Java 17, Spring Boot, PostgreSQL | Хранит последние результаты скоринга, считает сумму предложения, контролирует срок годности. Скоринг не инициирует |
| Адаптер Кредитного конвейера | Java 17, Spring Boot | Онлайн-передача заявок в Camunda и получение статусов |
| Адаптер скоринга | Java 17, Spring Boot | Один вызов на заявку, тайм-аут и предохранитель, публикация результата в Kafka |
| Кредитный модуль интернет-банка | React.js, SPA | Предложение, подача заявки, СМС-код. Ядро монолита не затрагивает |
| Витрина кредитов на сайте | PHP, React.js | Условия кредита и форма заявки |

Переиспользуются из MVP депозитов: API Gateway, Kafka, сервис уведомлений и кодов, адаптер АБС.

Логика принятых решений и выбора технологий:

- **Заявка идёт в Конвейер напрямую, а не через АБС.** Запрет на ускорение касается существующей интеграции по базе данных. Конвейер масштабируется горизонтально и работает 24/7, значит принимать заявки онлайн может. Старый путь для отделений сохраняется.
- **Предодобренные предложения не требуют предрасчёта.** Скоринги и так выполняются по другим поводам. Адаптер публикует каждый результат в топик, сервис предложений его сохраняет. Предложение видит тот, по кому есть свежий результат. Нагрузка на скоринг не растёт.
- **Срок годности результата обязателен.** Предложение — обязательство банка, а скоринг устаревает. Просроченный результат скрывается, клиент видит обычные условия.
- **Единый реестр заявок.** Сегодня заявка живёт отдельно в АБС и в Конвейере. Единый идентификатор позволяет менеджеру продолжить заявку с сайта, а не заводить вторую.
- **Отказ скоринга не блокирует подачу.** У адаптера тайм-аут и предохранитель, заявка принимается, скоринг выполняется при обработке в Конвейере.

### **Альтернативы**

1. **Подача заявок из каналов через АБС**
   - Единый путь для всех заявок, отделения и онлайн работают одинаково
   - Не нужны маршрутизация и адаптер Кредитного конвейера
   - Но заявка попадает в суточный обмен, срок в один день не выполняется, а нагрузка на перегруженную базу АБС растёт

2. **Массовый ночной предрасчёт скорингов**
   - Предодобренное предложение доступно любому клиенту, а не только тем, по кому есть свежий результат
   - Логика проще: витрина предложений всегда заполнена
   - Но это прямое нарушение запрета нагружать систему скоринга предрасчётами

**Ограничения решения**

1. **Охват предложений неполный.** Предложение видит только клиент со свежим результатом скоринга. Клиент, никогда не обращавшийся за кредитом, его не увидит.
2. **Предложение всегда предварительное** и подтверждается повторным скорингом: между расчётом и подачей ситуация клиента могла измениться.
3. **Новый клиент не получает кредит полностью онлайн** — нужна личная идентификация в отделении. Онлайн доступны заявка и предварительное решение.
4. **Решение принимает сотрудник кредитования.** Срок в один день зависит от графика работы, архитектура его не гарантирует.
5. **Два пути обработки заявок работают параллельно:** онлайн из каналов и суточный обмен из отделений. Это усложняет сопровождение.
6. **Зачисление средств проходит через АБС** и наследует её ограничения: вертикальное масштабирование и один ЦОД.
7. **Целевые показатели нагрузки не заданы** — число заявок в час и допустимая задержка вызова скоринга требуют уточнения.
